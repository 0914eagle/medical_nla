# 논문 표·그림 설계 — 2026-08-19

**대전제**: 믿을 수 있는 진단 설명은 모델이 말하는 것(CoT)이 아니라 검증된
방법으로 내부에서 읽어낸 것이며, 그렇게 읽은 내부 증거가 오류의 설명·예측·
교정을 더 잘 해낸다.

## 데이터셋

| 약칭 | 데이터 | 증거(cue)의 정체 | 텍스트 성격 | 역할 |
|---|---|---|---|---|
| **DDX** | DDXPlus | 문진 문항 + 값으로 만든 cue 문자열 | 템플릿 조립 | 정밀 계측 — span이 정의상 확정, 개입 쌍 제작 가능 |
| **MCR** | MedCaseReasoning (Stanford, CC-BY-4.0, 14,489 케이스) | **임상의 추론 문장에 딸린 원문 verbatim 인용** | 실제 case report 산문 | 실제 임상 텍스트 이식 |
| MedQA | MedQA-USMLE | 없음 | 객관식 문항 | 정확도 델타 전용 |

**두 데이터셋을 쓰는 이유**: DDX는 프롬프트를 cue로 조립하므로 span이 정의상
확정되고 개입 쌍을 정확히 만들 수 있지만 합성 텍스트다. MCR은 임상의가 근거로
지목한 원문 인용이 곧 cue라 같은 방법이 적용되면서 **실제 임상 산문**이다.
둘을 함께 쓰면 "합성 데이터에서만 되는 것 아니냐"와 "데이터셋 하나뿐"이라는
두 약점이 동시에 해소된다.

**개입 방식이 데이터셋마다 다르다**: DDX는 cue 목록에서 프롬프트를 재조립해
원본과 문자열 일치를 검증한다(construction-exact). MCR은 산문이라 재조립할
템플릿이 없으므로 **cue의 문자 span만 제자리 교체**하고 나머지 바이트는 그대로
둔다(span 치환). 어느 쪽이든 개입은 최소·정확하며, 교체된 span 외에는 두
프롬프트가 동일하다.

MedQA는 증거 span 주석이 없어 판독 채점에 쓰지 않고 Figure 3의 정확도 열에만
쓴다. 약물 도메인(PHEE 등)은 후속 확장으로 둔다.

## 가설과 명제

**가설 1 — output(CoT)은 실제 판단 근거를 반영하지 않는다**
- H1.1 CoT의 근거는 인과적이지 않다 — 절단·오염해도 답이 유지된다 · DDX, MCR
- H1.2 답을 바꾼 요인을 CoT는 언급하지 않는다 — cue/span 개입, 힌트 주입 · DDX, MCR
- H1.3 내부 상태는 output이 못 드러내는 정보를 갖는다 — 출력 신호가 못 잡는
  오답을 내부 신호가 예측한다 · DDX

**가설 2 — 기존 내부 도구는 탐지는 하되 케이스 고유 증거를 서술하지 못한다**
- H2.1 탐지만 보면 probe로 충분하다 (인정 명제) · DDX
- H2.2 probe·SAE·logit lens는 조합적 임상 증거를 출력할 수 없다 · DDX, MCR
- H2.3 증거의 보존 형태(보존/왜곡/반전/부재)를 구분하지 못한다 · DDX

**가설 3 — 검증 가능하게 설계된 자연어 판독이 그 격차를 메운다**
- H3.1 naive verbalization은 실패한다 — 진단명 타깃은 분류기로 붕괴하고,
  옳은 타깃도 틀린 위치에서는 실패한다 · DDX
- H3.2 올바른 설계는 학습에 없던 임상 증거를 읽는다 · DDX(합성 문진 cue), MCR(실제 case report 인용)
- H3.3 판독은 벡터에 인과적으로 종속된다 — 개입 추적, 문맥 무기억 · DDX(재구성), MCR(span 치환)
- H3.4 판독 가능성은 층·위치에 따라 체계적으로 변한다 · DDX, MCR은 L24 확인만

**가설 4 — 검증된 판독은 오류를 해부하고 성능을 개선한다**
- H4.1 오답은 내부 증거 상태로 유형화된다 · DDX
- H4.2 증거 인코딩 상태가 오답을 예측한다 (gold 미참조 = 순환 없음) · DDX
- H4.3 유형에 맞는 개입만 효과가 있다 · DDX
- H4.4 내부 감사 기반 개입이 출력 기반보다 정확도를 더 올린다 · DDX, MedQA

**주의**: 기존 결과는 경향성 확인용 pilot. 논문 수치는 통제·규모를 갖춰
재실행한다(표본 크기, 사전 고정, 예산 통일 — 각 항목의 통제 참조).

## 수치 정의

**① 오답 예측 AUROC** — 이진 라벨 y = [source 모델의 답이 오답], 점수 s는
행마다 다름. AUROC = 무작위 (오답, 정답) 쌍에서 오답에 더 높은 s를 줄 확률.
AP도 병기(base rate 명시 필수).

| 행 | 점수 s의 정의 |
|---|---|
| Answer confidence | 생성된 답 토큰들의 평균 log-prob (음수화) |
| Output-distribution signal | DDX: 26개 진단명을 각각 답 자리에 놓고 시퀀스 log-prob 계산 → softmax → **1등−2등 margin**(음수화) 및 entropy / MCR: 생성 시퀀스의 log-prob·entropy |
| CoT self-explanation | k=5회 CoT 샘플링 후 **답 불일치율**(self-consistency) |
| Linear probe | probe 예측 분포의 margin(음수화). **probe는 평가 풀과 분리된 split에서 학습** — 평가 행이 학습에 포함되면 무효 |
| Ours | **증거 인코딩률** = (판독에서 원형 보존으로 판정된 gold cue 수) / (그 케이스의 gold cue 총수). gold 정답을 참조하지 않으므로 순환 없음 |

**② 충실성** — 두 값 병기: `개입 반영률 / 문맥 암기율`. 상세 정의는 Table 2.
- 개입 반영률(판독) = 교체된 슬롯의 판독이 **새 cue의 내용**으로 바뀐 비율
- 개입 반영률(CoT) = 답이 바뀐 개입에서 **설명이 그 개입을 언급한** 비율
- 문맥 암기율 = 교체 후에도 판독이 **원본 cue**를 내는 비율

**③ unseen 임상증거 서술** — 학습에서 완전히 제외한 cue 문자열에 대한
**A+B 비율**. A = 자구 일치, B = 표현만 다르고 의미 완전 보존, C = 계열은
맞으나 속성 오류, D = 의미 어긋남/반전. 분모 = heldout 판독 행 수.
채점: 사람 수동(주) + LLM judge 제2 평가자(κ 보고, appendix).
Training-free 행은 형식 없는 다문단 출력이라 자동 지표(strict/soft) 병기.

**④ 오류 원인 유형화** — 가능/불가(○/✕). 우리 행의 ○의 근거는 Table 3.
(정량값은 Table 3(b)의 대각 우세 여부)

## Pilot에서 관찰된 경향

재실행 전 pilot에서, 출력 확신도의 오답 예측력은 AUROC 0.67–0.70 수준에
그친 반면 내부를 읽는 신호는 그보다 크게 높았다. 우리 판독은 학습에서
제외한 cue를 의미 수준으로 약 73% 복원했고, 개입 추적률은 0.99대·문맥
암기율은 0이었다. 무학습 판독(training-free verbalization)은 같은 활성값에서
내용을 담기는 했으나 지어낸 서술에 섞여 나와 자동 지표가 0.1~0.6 사이로
크게 흔들렸다. 논문 수치는 통제된 재실행으로 확정한다.

# Figure 1 — 설계 ablation

Results의 판독기 설계 절. **메시지**: naive verbalization은 실패한다. 타깃과 위치를 바꿔야 판독이 선다.
**검증 명제**: H3.1, H3.2 · **막아내는 반박**: "결국 LoRA 튜닝 잘한 것 아니냐"

형태: 4단계 × seen/heldout 쌍 막대. v1의 heldout은 막대 없음(0).

| 설계 | 타깃 | 추출 위치 | seen | heldout |
|---|---|---|---|---|
| v1 naive | 진단명 | format (마지막 토큰) | ▢ | ▢ |
| v3 | cue 목록 | format | ▢ | ▢ |
| v4 | 단일 cue | cue span (L32) | ▢ | ▢ |
| **v4 (ours)** | 단일 cue | cue span (**L24**) | ▢ | ▢ |

## 수치 정의
- **v1 행**: answer_hit = 판독이 낸 진단명이 source 모델의 답과 일치한 비율
  (seen), heldout은 **정답 진단명을 낸 케이스 수 / 800**
- **v3 행**: cue_recall = 출력에 등장한 gold cue 수 / 케이스의 gold cue 총수
  (lexical 채점기, 케이스 평균)
- **v4 행**: A+B 비율 (Table 1 ③열과 동일 정의)
- 주의: v1/v3/v4는 타깃 형식이 달라 지표가 다르다 → **막대 색을 달리하고
  캡션에 명시**. 비교의 요점은 절대값이 아니라 **heldout에서의 붕괴/성립**.
- appendix에 정확한 수치표 수록.

**Pilot에서 관찰된 경향**: 진단명을 타깃으로 한 v1은 seen에서 90%대를
기록하고도 학습에 없던 진단 800건에서 정답을 한 건도 내지 못했다(완전 붕괴).
타깃을 cue로 바꾼 v3은 format 위치에서 여전히 낮았고, 추출 위치를 cue 토큰
자리로 옮긴 v4에서 비로소 판독이 성립했으며 L24가 L32보다 높았다. 즉 타깃
교체와 위치 이동 **두 결정이 모두 있어야** 성립한다는 것이 pilot의 관찰이다.

|---|---|---|

## 수치 정의
- **cue 위치 곡선**: 각 layer에서 학습한 판독기의 heldout **A+B 비율**
  (Table 1 ③열과 동일 채점). 세 layer 모두 **동일 학습 데이터·타깃**,
  변수는 활성값을 뽑은 층 하나
- **답 위치 곡선**: 동일 recipe를 format 위치(프롬프트 마지막 토큰)에서
  학습·평가한 heldout **cue_recall**(lexical)
- **주석**: 같은 format 위치 활성값의 **선형 probe 진단 분류 정확도**(≈99%)
  — "정보가 없는 게 아니라 클래스 신호만 있다"
- 두 곡선은 채점 방식이 달라(수동 A+B vs lexical) **절대값 비교가 아니라
  곡선의 모양(역U자 vs 평평)이 메시지**임을 캡션에 명시

**Pilot에서 관찰된 경향**: cue 위치 곡선은 L16에서 낮고 L24에서 정점을 찍은
뒤 L32에서 다시 내려가는 역U자였다. 반면 답 위치 곡선은 세 층 모두 낮은
값에서 평평했고, 같은 활성값의 진단 probe 정확도는 99%에 달했다 — 그 자리에
정보가 없는 것이 아니라 클래스 신호만 남아 있다는 뜻이다.

# 인라인 실물 — 증거의 네 가지 보존 형태

Results의 판독 성질 절. 별도 그림 없이 본문에 삽입한다.

본문에는 정의 1문단 + 아래 2줄만. 전체 예시는 appendix.

```
gold: "chest pain even at rest"
  L24 → "chest pain at rest"                      [보존]
  L32 → "worse with exertion, relieved by rest"   [반전]
  ── probe: 두 경우 모두 "협심증 계열"로 동일 ──
```

## 수치 정의

**데이터**: 개입 쌍 — DDX는 construction-exact(재구성 프롬프트가 원본과 문자열
완전 일치 검증), MCR은 span 치환(cue 문자 span만 제자리 교체). 목표 규모
~1,000 swap쌍(500 케이스 × 슬롯 2개), 데이터셋별로 각각.

| 지표 | 정의 |
|---|---|
| 추적률 (ours) | 교체 슬롯의 판독이 **새 cue의 내용**을 낸 비율. 수동 판정 T/D/O/X 중 (T+D)/N — T=정확 추적, D=새 cue의 계열은 맞고 속성 오류, O=기타, X=원본 유지 |
| 원본 잔존 (ours) | X / N (교체 후에도 **원본 cue**를 읽은 비율) |
| phantom (ours) | 제거 변형에서 **삭제된 cue**가 출력에 재등장한 비율. 템플릿 어휘 겹침에 의한 오탐은 수동 배제 |
| retained 안정성 (ours) | 개입하지 않은 슬롯의 판독 성공률 (orig / swap / removed 각각) |
| 언급률 (CoT) | 답이 바뀐 개입에서 CoT가 **그 개입 대상 cue를 언급**한 비율. 판정 = LLM judge + 수동 검증(κ 보고). 판정 대상이 우리가 개입한 특정 cue 하나이므로 신뢰 확보 가능 |
| 답 변화율 (CoT) | cue 제거 시 답이 바뀐 비율 (= 그 cue의 인과적 기여) |
| 답 불변율 (CoT, Lanham식) | CoT를 절단·오염시킨 뒤 답이 그대로인 비율 (높을수록 설명이 답의 원인이 아님) |
| 미인정률 (CoT, Turpin식) | 힌트 주입으로 답이 바뀐 케이스 중, 설명이 힌트 영향을 언급하지 않은 비율 |
| 힌트 span 판독률 (ours) | 힌트 문장 위치에서 판독이 힌트 내용을 읽어낸 비율 (출력이 은폐한 원인의 내부 가시화) |

**Pilot에서 관찰된 경향**: 150쌍 규모의 pilot에서 판독은 교체된 cue를 거의
전부 따라갔고(0.99대), 원본 cue를 계속 읽은 경우는 한 건도 없었으며, 삭제된
cue가 재등장하는 phantom도 0.3% 수준이었다. 개입하지 않은 슬롯의 판독은 세
변형 모두에서 0.97 안팎으로 안정적이었다. CoT 쪽 열은 이번 재실행에서 처음
측정한다.

# Table 3 — 오류 해부학

Results의 오류 분석 절. Table 1 ④열의 실체이며 (a) 유형 분포와
(b) 유형×개입 두 부분으로 구성한다. **메시지**: 오답이 내부 증거 상태로 유형화되고, 유형에 맞는 처방만 효과가 있다.
**검증 명제**: H4.1 · H4.3 · **막아내는 반박**: "유형은 임의로 그은 선 아니냐"

**(a) 유형 분포**

| 유형 | 조작적 정의 | 비율 |
|---|---|---|
| 인지 실패 | 핵심 gold 증거의 판독 상태가 부재/왜곡 | ▢ |
| Distractor 과가중 | 증거 완비 + 내부 결론이 distractor 진단 지향 | ▢ |
| 통합 실패 | 증거 완비 + 내부 결론 오답 (distractor 아님) | ▢ |
| Decoding 실패 | 증거 완비 + 내부 결론 정답 + 출력 오답 | ▢ |

## 수치 정의 — 분류 알고리즘

케이스별 감사 레코드 = (E, S1, S2, O, gold)
- **E** = cue별 판독 상태 ∈ {보존, 왜곡, 부재} (cue 위치 L24 판독, 4형태
  기준 자동 분류 + 표본 수동 검증). "증거 완비" = 그 케이스의 **핵심 gold
  cue가 모두 보존** (핵심 cue의 정의는 사전 고정)
- **S1** = 26-way likelihood 분포의 top-1 (모델 자신의 결론)
- **S2** = linear probe 예측 (상태의 gold-지향 신호)
- **O** = source가 실제 출력한 답
- 분류 순서: E 불충분 → 인지 실패 / E 완비 ∧ S2=gold ∧ O≠gold → decoding /
  E 완비 ∧ S가 distractor 지향 → distractor 과가중 / 나머지 → 통합 실패
- "distractor 지향"의 정의: 내부 결론이, 그 케이스에 존재하지만 gold와
  무관한 cue로 설명되는 진단을 가리킴 (사전 정의된 혼동쌍 목록 사용)

**(b) 유형 × 개입 flip rate** — 분류 타당성의 인과 검증

| | 증거 재주입 | Verifier 재생성 | Generic 재고 |
|---|---|---|---|
| 인지 실패 | ▢ **(예측: 낮음)** | ▢ | ▢ |
| 통합/distractor | ▢ **(예측: 높음)** | ▢ | ▢ |
| Decoding | ▢ | ▢ **(예측: 높음)** | ▢ |

## 수치 정의
- **flip rate** = (개입 후 정답이 된 케이스 수) / (그 유형의 오답 케이스 수)
- 셀당 최소 표본 50~100 (부족한 유형은 오답 케이스 추가 수집)
- 개입 예산 통일: 모든 셀에서 재시도 1회, 프롬프트 추가 길이 동일
- **유형 정의와 예측을 개입 실행 전에 문서로 고정** (사후 조정 시 순환)

**왜 이것이 검증인가**: "이 오답의 진짜 원인"에는 gold가 없다 — 사람도 모델
내부를 못 보므로 외부 판정 불가. 대신 각 유형은 **원인에 대한 주장**이고,
주장이 참이면 예측이 따라 나온다(증거가 내부에 없으면 프롬프트로 되돌려줘도
소용없어야 함). 분류가 무의미하면 개입 효과는 유형에 무관하게 비슷해야 한다.
**인지 실패 행의 '낮음'은 우리에게 불리한 음성 예측이라 우연히 맞기 어렵고**,
적중하면 "개선은 그냥 재시도 덕분"이라는 대안 설명도 배제된다.

**반대 결과 시**: 모든 칸이 비슷하면 "유형 분류는 예측력이 없었다"고 정직하게
보고하고, 개입 결과(Figure 3/Figure 4)만 주장한다.
