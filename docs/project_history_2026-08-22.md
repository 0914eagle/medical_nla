# Medical-NLA 프로젝트 전사(全史) — 무엇을 했고, 왜 바뀌었나 (2026-08-22)

처음 읽는 사람을 위한 문서다. 이 프로젝트가 어디서 출발했고, 어떤 결과가
어떤 가설을 죽였으며, 지금 무엇을 주장하는 상태인지를 시간순으로 적는다.
각 단계마다 **그때 믿었던 것 → 잰 것 → 알게 된 것 → 바꾼 것**의 구조로 쓴다.

`EXPERIMENTS.md` 또는 해당 문서에 있다.

## 0. 배경 지식 — 이것만 알면 읽을 수 있다

**대상 모델(backbone)**: `google/gemma-3-12b-it`. 48층 트랜스포머.
환자 케이스를 주고 진단명을 답하게 한다.

**NLA(Natural Language Autoencoder)**: 모델 내부의 활성값(activation, 어떤
토큰 위치에서의 은닉 벡터)을 **자연어 문장으로 읽어내는** 도구.
AV(Activation Verbalizer)가 그 절반으로, 벡터 하나를 받아 그것이 담고 있는
내용을 문장으로 쓴다. 우리는 upstream이 일반 텍스트로 학습해 공개한
`kitft/nla-gemma3-12b-L32-av`에서 출발했다.

**왜 이 도구인가**: 내부를 보는 기존 도구는 출력이 라벨이다. linear probe는
"클래스 7, 확률 0.93", SAE는 "feature #4821 활성". 미리 정한 어휘 밖의 내용
— 조합, 불확실성, 갈등 — 은 서술할 수 없다. NLA만 문장을 낸다. 이 관찰은
프로젝트 전 기간 동안 한 번도 반증되지 않았고, 지금도 논문 가설2의 기둥이다.

**데이터(DDXPlus)**: 합성 감별진단 벤치마크. 케이스 = 나이/성별 + 소견
(cue) 목록 + 정답 진단(49종) + 감별진단 순위. 소견이 구조화된 문자열이라
"판독이 소견을 읽었는가"를 **기계 채점**할 수 있는 것이 채택 이유였다.

**교수님이 주신 3축** (프로젝트의 대전제, 지금까지 불변):

1. **설명** — 모델이 내부에서 무엇을 고려했는지 사람이 읽게 꺼낸다
2. **진단** — 답이 틀릴 것 같은지를 내부 신호로 예측한다
3. **교정** — 그 신호로 답을 실제로 고친다

## 1. 1기 (~8월 중순) — 헤드라인이 강했고, 전부 교란이었다

### 그때 믿었던 것

첫 Medical-AV(진단명을 타깃으로 LoRA 튜닝한 판독기)의 수치는 겉보기에 논문이
끝난 것 같았다.

| 지표 | 값 |
|---|---:|
| source 답 ≠ AV 판독 → source 오답 예측 AUROC | **0.9427** |
| source가 틀린 케이스에서 AV가 정답을 읽음 | **83.4%** |
| AV answer_hit | 87.0% |

서사: "모델이 답을 틀려도 내부에는 정답이 있고, 우리가 그걸 읽는다."
3축이 모두 닿는 것처럼 보였다.

### 잰 것 — 스스로 세운 반론 두 개

**교란 A**: linear probe가 같은 활성값에서 진단을 99.17%로 분류한다. 그렇다면
AV는 활성값을 "읽는" 게 아니라 26개 클래스를 "암기 분류"하는 것으로도 그
수치가 나온다. **교란 B**: 평가셋이 오답 농축(74%)이었고, AV가 gold로 학습돼
"AV ≠ source"가 정답 정의와 정보적으로 겹친다(순환).

통제 실험 세 개를 돌렸다.

| 실험 | 결과 |
|---|---|
| A. probe 대조 | probe 불일치 신호가 AUROC **1.0000** — AV(0.9282)보다 낫다. 오류 탐지는 NLA 고유 기여가 아니다 |
| B. 진단-heldout | 학습 안 한 진단 8클래스에서 answer_hit **0.29~0.35로 붕괴** — v1은 판독기가 아니라 seen-class 분류기였다 |
| C. 바닐라 대조 | 무학습 AV도 내용은 이미 말함 — LoRA가 내용을 만든 게 아니다 |

### 알게 된 것 / 바꾼 것

**0.94는 우리 것이 아니었다.** 진단명을 타깃으로 학습하는 한 "읽기"와
"분류"가 구분되지 않는다. → 타깃을 **진단명에서 소견(cue)으로** 바꿨다.
소견은 케이스마다 다르고 문자열이 학습에 없을 수 있어서, 암기로는 못 맞힌다.

출처: `professor_presentation_2026-08-17.md` §0.5~1.

## 2. 2기 (8/16~17) — 판독기를 도구로 만들고 검증한 시기

### 설계 변경 세 가지

1. **cue-position 추출**: 활성값을 답 위치가 아니라 **각 소견의 토큰 위치**에서
   뽑고, 타깃은 그 소견 하나. 케이스당 여러 행.
2. **cue-string heldout**: 유니크 소견 문자열의 25%를 학습에서 완전히 제외.
   판독기가 학습에서 한 번도 본 적 없는 문자열을 읽어내면 그것은 암기가 아니다.
3. **counterfactual**: 소견 하나만 바꾼 프롬프트 쌍. 판독이 바뀐 소견을
   따라가는지로 충실성을 잰다.

### 결과 (전수 수동 분류 포함)

| 검증 | 수치 |
|---|---|
| heldout cue 의미 수준 읽기 | L24 73.1% (438행 전수 수동) |
| layer 지도 | 판독 가능성은 cue 위치에서 **L24 정점**, 답 위치는 전 layer에서 증거가 아니라 결론만 |
| counterfactual | swap 추적 **99.3%**, 암기 0%, phantom 0.3% (150쌍 전수) |
| 반암기 | 출력이 train cue보다 unseen gold에 더 가까움 (L24 63%) |

여기서 도구가 섰다: **읽고(heldout), 특정 위치를 읽고(layer 지도), 개입을
따라간다(counterfactual).**

출처: `results_2026-08-16_v4_cue_position.md`, `results_2026-08-17_*.md`.

## 3. 3기 (8/19~21) — 인프라 정비와 "죽은 가설" 다섯

8/17 이후 계획은 "오답노트"였다: 모델이 틀린 케이스에서 판독으로 오류를
4분류(missing cue / distractor overweighting / late drift / decoding mismatch)
한다. 그 준비로 채점·데이터 파이프라인을 정비하다가 측정 자체의 결함을 여럿
찾았고, 고치고 나니 **작업가설이 연쇄로 죽었다.**

### 3.1 측정 정비 (전부 논문 이전에 잡혀서 다행인 것들)

| 발견 | 수정 |
|---|---|
| 채점기가 `URTI`≠"upper respiratory tract infection"으로 오답 처리 → 정확도 0.2920으로 과소 | 49라벨 별칭 테이블(`src/ddxplus_aliases.py`) → **0.3724** 확정. 별칭을 기록하지 않아 재채점마다 어긋나던 것도 수정(기록 의무화) |
| `--limit`이 파일 앞부분만 취함 → 진단 편중 표본 (7개 스크립트) | 공용 `sample_rows` 도입 |
| 후보 집합을 표본에서 수집 → 49-way가 2-way로 | 전체 파일에서 수집으로 수정 |
| 학습 loss 0.0002를 누출로 오독 | 타깃의 83%가 고정 XML 스캐폴드 → content/scaffold loss 분리, content로 선택 |
| `PE`(폐색전증 별칭)가 "as-pe-ct" 안에 매칭 → 누출 케이스 과대 집계 | 단어 경계 매칭 → 984건(20.1%)이 아니라 **768건(15.7%)** |

### 3.2 죽은 작업가설 다섯 (D1~D5)

각각 우리가 세웠고, 우리가 재서 죽였다.

| # | 가설 | 반증 | 대체 이해 |
|---|---|---|---|
| D1 | 일반도메인 NLA는 의료 활성값을 못 읽는다 | 바닐라 AV가 heldout **0.7247** (우연 0.088) — 어댑터 0.7506과 사실상 동급 | LoRA의 기여는 정확도가 아니라 **계측성**: 형식 0.05→1.00, 길이 1557자→52자, 정밀도 0.075→0.671 |
| D2 | CoT는 근거를 빠뜨린다 | 체인이 소견의 **92.3%**를 받아씀 (우연 17%) | 빠뜨리지 않는다. 문제는 다른 곳에 있다 (아래 D5·1-2) |
| D3 | CoT는 정확도를 해친다 | 320케이스 짝지음, 차이 −1.9%p, **p=0.4966** | 다만 답은 17%에서 바꾼다 — 정확도와 무관한 방향으로 |
| D4 | 판독이 오답을 예측한다 | 진단명만 아는 예측기 AUROC **0.9327**; 진단 고정 시 판독 특징 **0.48~0.51** | DDXPlus에서 오답은 케이스가 아니라 **라벨이 결정**한다. 이 코퍼스에서 축2는 질문 자체가 성립 안 함 |
| D5 | CoT는 답을 움직인 편향에 침묵한다 (Turpin 재현) | 소견서 언급률 **0.9833** — 답을 안 바꾼 통제군도 0.9875 | 침묵(누락)이 아니라 **무차별**: 전부 언급하므로 언급이 정보가 아니다 |

부수로 DDXPlus 자체의 성질도 확정됐다 (`ddxplus_as_a_benchmark_2026-08-22.md`):

- 케이스 15.7%는 제시문에 진단명이 그대로 적혀 있다 (가족력/과거력 문항).
  그 케이스 정확도 0.7031 vs 나머지 0.3110.
- 오답은 감별진단 안에 머문다 — 상위 3위 내 0.9012, 평균 순위 1.8.

### 이 시기의 교훈

다섯 번 모두 같은 실패 방식이었다: **결과를 먼저 보고 해석을 맞췄다.**
이후 모든 가설에는 반증 조건을 실행 전에 문서로 적는다
(`hypotheses_and_paper_outline_2026-08-22.md`).

## 4. 4기 (8/22) — 소견서 개입: 살아남은 실험

### 왜 이 설계인가

D5가 죽으면서 남은 질문: 답을 실제로 움직이면서, 설명이 그 역할을 식별해야
하는 원인을 만들 수 있는가. 소견을 바꾸는 것은 답이 안 된다 — 소견은 차트에
적혀 있고 체인이 92%를 받아쓰므로 언급하는 게 정상이다. 필요한 것은
**차트 밖에서 온, 임상적으로 실재하는 교란**이다. 의뢰 소견서(referring
note)의 의심 — anchoring bias — 가 그것이다.

### 데이터 구성 (`make_hint_injection_cases.py`)

한 케이스를 **문장 하나만 다른 4개 조건**으로 복제한다.

| 조건 | 삽입 문장 |
|---|---|
| `none` | (없음) |
| `neutral` | The referring note requests evaluation. (위약 — 내용 없음) |
| `wrong` | The referring note suspects {감별진단 중 정답 아닌 1순위}. |
| `correct` | The referring note suspects {정답}. |

설계 규칙과 이유:

1. **원래 맞히던 케이스만** (4,900 중 1,747). 틀리던 케이스는 소견서가
   움직였는지 판정 불가.
2. **문장은 소견 뒤·질문 앞**. causal attention 하에서 소견 위치 활성값이
   네 조건에서 **비트 단위로 동일**해진다. → "증거 표현은 불변인데 답이
   바뀐다"를 가정 없이 말할 수 있고, 활성값 추출도 한 번으로 끝난다.
3. **틀린 의심은 감별진단 1순위**. 모델이 즉시 기각할 병명은 아무것도 못
   움직이고, 그러면 실험이 성립하지 않는다.
4. 차트가 진단명을 이미 쓰는 케이스는 버리지 않고 `gold_in_prompt`로 표시해
   층화한다.

### 결과 (직답, 진단명이 차트에 없는 1,220케이스)

| 조건 | 정확도 | 대비 |
|---|---:|---:|
| 소견서 없음 | 0.9910 | — |
| 위약 | 0.9344 | −5.7%p |
| **틀린 의심** | **0.7598** | **−23.1%p** |

**제안 고유 효과 = 17.5%p (위약의 4배).** 반증 조건("위약도 비슷하게
떨어지면 효과는 문장 침입이지 제안이 아니다")은 걸리지 않았다.

부수 결과 둘:

- **차트가 진단명을 이미 쓰면 제안이 힘을 잃는다**: 제안 고유 효과 −17.5%p
  vs −0.8%p. 앵커링은 증거만으로 감별되지 않을 때 일어난다.
- **CoT는 이 편향을 무력화한다**: 같은 케이스 CoT에서 0.5787 → 0.5872
  (효과 없음). 체인을 읽으면 소견서를 명시적으로 기각한다 — "likely a red
  herring", "likely premature". Turpin(숨긴다)과 정반대.

소견서가 답을 움직인 케이스: **324/1,747** (그중 의심된 병으로 간 것 95).
이것이 다음 단계의 모집단이다.

## 5. 지금 — 가설이 무엇으로 바뀌었나

### 시작 가설 → 현재 가설 대응표

| 시작 (8월 초) | 무슨 일이 있었나 | 현재 (8/22) |
|---|---|---|
| "내부에 정답이 있고 AV가 읽는다" (AUROC 0.94) | 교란 2개로 붕괴 (1기) | 폐기. 오류 탐지는 probe도 하는 일 |
| "LoRA로 의료 판독 능력을 만든다" | 바닐라가 이미 읽음 (D1) | **가설3**: LoRA는 능력이 아니라 **계측성**을 만든다 |
| "CoT는 근거를 빠뜨리거나 감춘다" | 92% 받아씀, 98% 언급 (D2·D5) | **가설1**: 체인은 전부 말하기 때문에 **무엇이 답을 결정했는지 식별 못 한다** (누락이 아니라 무차별) |
| "판독으로 오답을 예측한다" (축2) | 라벨이 오답을 결정 (D4) | DDXPlus에서는 질문 불성립 — 한계/데이터 절로. MCR 이전은 교수님 결정 대기 |
| (없던 것) | 소견서 개입 설계·확정 (4기) | **핵심 실험**: 증거 불변 개입 + 위치별 판독으로 **원인 귀속/국소화** |

### 현재의 가설 사슬 (교수님 템플릿 형식, `storyline_and_tables_2026-08-22.md`)

1. **가설1**: CoT 해석은 **인과 귀속 불가** 문제가 있다 ⇒ 내부를 봐야 한다.
   (주의: 성능 문제가 아니다 — CoT는 정확도도 같고 편향도 막는다. 설명으로서
   못 쓰는 것이다.)
2. **가설2**: probe/SAE는 내부는 보지만 **서술 불가** ⇒ 방식을 바꿔야 한다.
3. **가설3**: 기존 NLA는 서술은 하지만 **계측 불가** ⇒ Medical-NLA(형식·위치·
   layer가 고정된 판독기)를 제시하고, 증거 불변 개입 위에서 사용한다.

### 논문 절별 채움 상태

| 절 | 상태 |
|---|---|
| 방법 / 계측기 검증 / 벤치마크 특성 / CoT 기준선 / 소견서 개입 | **수치 확정, 쓰면 됨** |
| 국소화 (위치별 판독 — 체인 vs 판독 귀속 대결) | 추출 완료, **판독 실행 대기** ← 논문의 성패 |
| 교정 (판독 되먹임으로 편향 되돌리기) | 국소화 이후 |

### 지금 걸려 있는 단 하나의 질문
