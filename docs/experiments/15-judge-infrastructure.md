## codex를 판정자로 쓰는 법

API 키 없이, `codex` CLI를 자식 프로세스로 띄운다:

```bash
codex exec --sandbox read-only --ephemeral --skip-git-repo-check \
  --output-last-message FILE -    # 프롬프트는 stdin
```

- 배너(`model: gpt-5.6-sol`)가 **stderr로** 나간다. 처음에 stdout만 보다가
  `judge_model`이 `codex-default`로 기록됐고, 지금은 두 스트림을 다 본다.
- `--output-last-message`가 답만 파일로 준다.

`gpt-5.6-sol`은 Codex 실행 당시의 라우팅 이름이며 고정된 공개 API snapshot을
보장하지 않는다. 논문 재현물에는 실행일, CLI 버전, stderr의 전체 모델 배너,
프롬프트 해시와 raw 응답을 보존한다. 핵심 판정은 가능하면 명시적 버전의 외부 API
모델로 한 번 더 실행한다.

## #3이 왜 몇 주 걸렸나 — 형식 문제였다

`make_readout_judge_requests.py`는 API가 없던 시절 설계라 **120쌍씩 묶은
붙여넣기용 청크**를 썼다. 배치는 붙여넣기의 제약이었고, 그 제약이 **붙여넣기로는
피할 수 없는 실패**를 안고 있다 — 판정자가 한 줄을 건너뛰거나 번호를 바꾸면
**그 뒤 판정이 전부 밀리고**, 하류에서 아무도 알 수 없다.

`--requests`가 쌍 하나당 요청 하나로 낸다: 밀릴 수 없고, 죽어도 쌍 단위로
이어지고, 비용은 루브릭 반복(약 300토큰)뿐이다. `--from-judge`가 결과를
`apply_readout_judgements.py`가 읽는 형식으로 되돌려, 붙여넣기 경로와 판정
경로가 같은 자리에서 만난다.

**파싱 실패는 버리고 센다. 기본값으로 채우지 않는다** — 답하지 못한 판정자는
결측이고, 어떤 기본값이든 재려는 비율을 움직인다.

## 이 프로젝트의 규칙 하나

~~**438행 채점의 채점 주체 표기는 외부 판정자가 대체할 때까지 비워 둔다.**~~
**해소 08-24** → [16](16-readout-semantic-judging.md). 규칙은 지켜졌다 — 사람
2차 채점이나 자기 일치율로 메우지 않고 외부 판정자(`gpt-5.6-sol`)를 기다렸다.

해소된 방식은 "대체"가 아니라 **병기**다. 손채점(저자)과 판정자를 나란히
싣고 κ를 함께 보고한다. 어느 한쪽으로 갈아끼우면 그것도 결국 채점자 하나의
주장이고, 두 채점자가 같은 238쌍에서 얼마나 갈렸는지가 어느 한 숫자보다
강하다. Figure 2에서 뺐던 A+B 줄은 이 provenance와 함께 돌아온다 — 단
**쌍 단위와 행 가중을 모두** 적는다(L24에서 둘의 차이 10.9%p가 채점자
차이 4.3%p보다 크다).

n도 정정됐다. 이 작업을 1,314(438행×3층)로 잡았던 것은 행 기준 추정이었고,
고유 (gold, readout) 쌍으로 접으면 **238**이다.
